# 桌面宿主、协议端与适配器的职责

一键包负责部署、运行环境和进程管理。MaiBot 负责插件配置与运行时。
NapCat / SnowLuma 的安装、登录、连接配置和启停独立于 MaiBot。

## 宿主接口

- `init`：检查和修复运行环境。
- `protocols`：账号、后端选择、协议端 WebUI 凭据、组件重装。
- `adapters`：用户显式发起的连接同步、官方 QQ 配置和适配器启用状态。
- `services`：通用进程启停、输出和健康检查。

`ProtocolBackendManager` 不接收 MaiBot 路径，不读取或修改插件配置。
`ProtocolComponentManager` 负责协议端组件维护，保留原有数据保护和回滚逻辑。
`InitManager` 保留兼容的调用入口，委托给上述模块；协议端配置流程不需要 Core 在线。

## 配置同步

设置账号和切换 NapCat / SnowLuma 只修改协议端配置及宿主选择记录。
不会自动启停 MaiBot 的适配器，不再从适配器 TOML 中获取端口和 token。
既有协议端配置优先使用自身的连接参数，旧宿主记录作为回退。

用户点击「同步连接配置」时，宿主读取当前协议端的 OneBot 地址、端口和 token，
通过 `MaiBotAdapterClient` 调用 MaiBot API 更新适配器的 `client` 配置。
该操作不重写协议端配置，不改变适配器启用状态。
宿主设置优先独立工作；API 不可达、认证失败或版本不支持时报告错误，不回退写插件文件。

目前复用 MaiBot 已有的接口：

- `GET /api/webui/plugins/config/{id}`：读取配置。
- `PUT /api/webui/plugins/config/{id}`：提交局部配置，由 MaiBot 合并与校验。
- `POST /api/webui/plugins/config/{id}/toggle`：修改启用状态并应用到插件运行时。

客户端只允许 `maibot-team.snowluma-adapter` 和 QQ 官方适配器，不提供通用插件管理。
启用/停用前读取当前状态，已达到目标时不调用 toggle；本客户端的修改请求串行执行，
不自动重试 toggle。其他客户端同时修改状态仍可能产生竞争，异常结果会返回给用户。
后续可由 MaiBot 提供幂等的目标状态接口，替换当前 toggle 适配。

## 已移除的重复实现

删除了通用插件市场、安装更新、配置 Schema 推断、评分等客户端及 `plugins:*` IPC。
删除了统计 HTML 解析和 `statistics:*` IPC。相关功能使用 MaiBot WebUI。
业务数据备份、聊天和桌面桥的进一步收敛不属于这次改造范围。

## 首次启动

宿主只显示运行环境准备界面。Core 就绪后交给 MaiBot WebUI，不再叠加手动「已完成」按钮，
也不维护称呼、聊天测试和协议端配置的第二套首次向导。
通过 `GET /api/webui/setup/status` 的 `is_first_setup` 字段自动识别完成或跳过向导。
请求读取当前实例的最新凭据，以适应首次配置中的密码变更；网络、认证和解析失败继续等待，
不会把端口就绪、页面跳转或失败响应当作完成。完成后记录宿主引导状态，不强制切换页面。
正常完成模型配置后，由 MaiBot WebUI 自己跳转到「聊聊」，提示用户发送问候并体验回复。
一键包不再维护第二套试聊侧栏，也不截断 WebUI 的后续引导。

试聊页面只在本次用户发送消息并收到新回复后提供「配置消息平台」入口，历史消息不算试聊结果。
该入口通过独立的 webview preload 请求宿主切换页面，只暴露导航能力；宿主校验消息来源为当前
本地 MaiBot 实例。浏览器独立运行时不显示宿主平台入口。
尚未添加平台时，宿主只显示消息平台卡片；添加后再显示协议端选择、高级设置和提示区。
「新增平台」是显式连接流程：先保存协议端配置，再通过 MaiBot API 同步并启用适配器，最后启动
协议端。单独保存账号和切换后端仍不修改适配器。
